# Go/client audit reconciliation

Current read-only source inspected: `internal/httpapi/api.go`, `auth-input.go`, `activity.go`, `internal/auth/service.go`, `internal/core/model.go`, `internal/store/social.go`, `activity.go`, and `openapi.yaml`.

- Auth exact keys: email-verify = phone_number,email; confirm = otp,device_id; refresh = refresh. CHECK_EMAIL returns no challenge. OTP is 22 base64url characters + dot + 43 base64url characters. Invalid/expired/used/locked all return 401; client deliberately does not invent separate server reasons. UI groups these, provides resend and a 60-second countdown, and honors Retry-After on 429.
- Numeric item IDs are mapped to domain strings only at the adapter boundary. People use author_id as their public user ID, not their numeric pagination ordinal. Shop/group IDs come from root list responses; products fetched separately. Current profile ID determines outgoing messages.
- Discover fetches type and q from Go on each category/query change; stale results are ignored. No unsupported subtype query is sent; subtype metadata is absent in Go and remains a parity gap.
- PUT/DELETE item like/save/follow; POST/DELETE group join. No bodies on relation or join requests. Create DTO contains only supported fields. Plain text posts work; real media/repost compose is blocked with an explicit unsupported message rather than silently dropping attribution. Mood/location are not sent or asserted persisted. Comments send body only; reply_to not supported.
- Go now has ActivityStore routes (added since the reported audit snapshot): GET notifications; PATCH notifications/{id}/read; POST items/{id}/shares; GET cart, PUT/DELETE cart/{productId}; PUT/DELETE users/{userID}/follow. Client uses these exact routes. If ActivityStore is nil or routes are not deployed, 404 is surfaced, never mock data/success. Deployment/migration and endpoint integration still require Go-owner verification.
- ProfilePatch now has optional Name/Bio pointers and SQL COALESCE in current source. Client PATCH bio only, maps returned complete profile; regression test checks returned name retained. This is source evidence, not a live database test.
- Important backend follow-ups: expose relation/membership flags and counts, resolved author names, shop contacts/hours/reviews, group rules/recent posts, media, post location/mood/type and attributed reposts. Current generic Item cannot represent baseline parity. Clarify notification navigation metadata; subtype filtering metadata; persisted profile grid; complete next-page pagination. Device/plugin, pinning and live integration remain release blockers.

No means of messaging the other running agent is exposed here; this file is the handoff, not a claim that Go acknowledged it. Backend source is never edited by the Flutter task. Parent reports compose validation succeeded but runtime is blocked by OCI permissions; no container/E2E success is inferred.
